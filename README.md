# Personal Corp — Gordey_ap01

Локальный штаб для проектов и постепенного внедрения Personal Corp 3: действующий реестр портфеля, задачи, доказательства результата, ежедневный обзор и автономная HTML-панель.

Python 3.10+, стандартная библиотека. Без установки пакетов, аккаунтов и API. Код переносим; личное состояние хранится только в игнорируемой папке `.local/`.

```powershell
python corp.py init --portfolio "ПУТЬ/portfolio/snapshot.json"
python corp.py refresh
python corp.py doctor
python corp.py daily
python corp.py dashboard
```

`init` не перезаписывает существующую настройку. Портфель — JSON с массивами `projects` и `github`; проект может содержать `label`, `path`, `projectId`, `stage`, `decision`, `next_goals_proposed`, `sources`. Внешний файл только читается. `refresh` проверяет наличие зарегистрированных папок, не запускает приложения и не читает их содержимое. Возраст исходного обзора выводится явно.

Результаты: `.local/dashboard.html`, `.local/daily.md`, `.local/inventory.json`. Панель работает как локальный файл без сервера, внешних шрифтов, аналитики и сетевых запросов. Она показывает сохранённый снимок; после работы выполнить `refresh`/`dashboard` и обновить вкладку.

После подключения Obsidian `open-hq.cmd` обновляет представление и открывает «Сегодня» в хранилище. `open-browser.cmd` открывает HTML-панель. Оба используют `launch_hq.py`: импортируют прежний обзор, пересобирают панель и заметки. Источник портфеля не перепроверяется; фонового исполнителя нет.

## Вход через Obsidian

«Сегодня» — главная страница. В «Проектах» находятся доска карточек с группировкой и редактируемая таблица. В «Обзорах» — полные отчёты. Новые мысли и отзывы записываются во «Входящие» и «Мои решения».

```powershell
python setup_obsidian.py --vault "ПУТЬ/существующее-хранилище" --executable "ПУТЬ/Obsidian.exe"
python launch_hq.py --check
python launch_hq.py
```

Используются встроенные Markdown и Bases; дополнительные плагины не нужны. Настройка добавляет раздел `Штаб`, отдельный CSS-фрагмент и группу закладок. Для хранилища включается открытие заметок в режиме чтения; кнопка с карандашом возвращает редактирование. Прежние настройки перед изменением сохраняются в `.local/obsidian-backups`. Ярлык Windows должен запускать установленный `pythonw.exe` с абсолютным путём к `launch_hq.py` в аргументах.

В карточках «Мой этап», «Следующий шаг» и «Фокус» принадлежат владельцу. Доска группирует по этапу; галочка фокуса выводит проект на главную. Изменение этапа — личный план, оно не меняет выполнение/приёмку задач Personal Corp. «Разобрать» по умолчанию не означает, что проект не начат.

`python corp.py obsidian` обновляет подключённое представление. Обновляются только блоки между маркерами `personal-corp:begin/end`. Свойства карточек, разделы личных заметок, входящие, журнал решений и настройки Bases сохраняются. Изменённый владельцем блок фактов не перезаписывается: конфликт и новая версия сохраняются локально, ярлык показывает сообщение. Перед заменой сохраняется предыдущая версия управляемого файла.

Обновление запускается ярлыком, а не по фоновому таймеру. Отзывы из Obsidian агент читает при следующем обращении; автоматическая приёмка и публикация не выполняются. Основная очередь остаётся в `.local/tasks.json`, исходный портфель — во внешнем реестре.

Документация форматов: [Obsidian URI](https://obsidian.md/help/uri), [Bases](https://obsidian.md/help/bases/syntax), [вид карточек](https://obsidian.md/help/bases/views/cards).

```powershell
python corp.py task add --id PC-001 --title "Подготовить результат" --department studio --priority 1 --acceptance "Есть пригодный к использованию файл"
python corp.py task start PC-001
python corp.py task review PC-001 --evidence "полный/путь/к/результату.html" --note "Проверено локально"
python corp.py task list
python corp.py retro
```

Состояния: `ready` → `in_progress` → `review` → `done`. `review` требует существующий локальный файл; `done` требует явную приёмку владельца. Для неё предусмотрена команда `task accept ID --note "Решение владельца"`; агент самостоятельно её не вызывает. `task block ID --note "Что требуется"` и `task ready ID` сохраняют историю переходов. Одновременно допускается одна задача `in_progress`. `daily` показывает сначала эту задачу, иначе первую готовую по приоритету; задачи в `review` выделены отдельно.

Очередь — `.local/tasks.json`, изменения записываются атомарно и под блокировкой; отчёты являются производными. `--state ПАПКА` позволяет использовать отдельное состояние для испытаний. Файлы с данными не входят в публичный репозиторий. Для переноса личного штаба нужна отдельная закрытая резервная копия `.local/`; Git сохраняет только код.

Методические источники: [Personal Corp 3](https://sereja.tech/bukvitsa-personal-corp/), [personal-corp-os Серёжи Риса](https://github.com/serejaris/personal-corp-os). Это самостоятельная адаптация под существующий портфель владельца; совместимость со всеми командами upstream не заявляется. Отделы здесь — области ответственности в одной очереди; отдельные агенты и фоновая работа не запускаются.

Проверки: `python -m unittest discover -s tests -v`.
